# agent-context

How `tai agent` copes with the model's small, fixed context window (`Model.context`, from the catalog's `context_window`): phased work, where each phase starts with a fresh context, and compaction, which replaces a long conversation with a summary. Both sit on top of the UI-independent loop in `agent/loop.py`, which reports context use through `Usage` events (`Agent.tokens`).

## Phased work (`agent/phases.py`)

- `/phase start <goal>` makes `.tai/work/<date>-<slug>/` (`notes/`, `tools/`, `tests/`, never reusing a folder) and runs phases one by one. **Each phase starts with an empty message list** (`PhaseRunner.begin` → `Agent.clear`): its first message (`PhaseRunner.prompt`) carries the task, the phase goal, every earlier phase's handoff and files, the later phases, and `plan.md` (20K chars). Everything else must be in files. The aim is a whole context window per phase, since the device's windows are small and there is no compaction.
- `state.json` is written only by tai: goal + phases (`name`, `goal`, `status` pending/active/done, `handoff`, `files`). The model owns `plan.md` and the rest of the folder. The folder is in the project on purpose, so the user can read it and commit it if they want.
- Phases: `explore` and `plan` are fixed (`FIRST_PHASES`). The model ends a phase with the `phase_done` tool (handoff, files, `next_phases`), which ends the turn after that step (`Agent.end_turn(TurnEnd("phase_done"))`). `next_phases` replaces the phases after the current one; the plan phase must give them, or the tool returns an error.
- While attached, the runner adds the `# Phased work` section to the system prompt and the `phase_done` tool, sets `Agent.auto_allow` so **write/edit inside the work folder don't ask** (everything else asks as usual), and sets `Agent.budget`. `/phase stop` removes all of it; the folder stays.
- Context budget (`loop.Budget`, only during phased work): after a step with tool calls, at 80% of `AgentConfig.context_window` the loop appends one user message asking the model to write its notes and call `phase_done`; at 95% it ends the turn with `TurnEnd("context_full")`. The TUI then offers `/phase redo` (fresh context, the files stay).
- TUI: after `phase_done`, `PhaseGateScreen` asks y / a (always, this run: `PhaseRunner.auto`) / n before starting the next phase; `/phase next` starts it later. `/phase next` refuses while the current phase is still in progress in this context (`in_progress`). The title shows `phase 2/4 · plan`. Each phase is saved as its own agent session named after it (`AppInfo.on_new_context`, set in `command.py`). `/phase resume` re-attaches the newest `state.json` in this folder and starts its current phase fresh.
- Tests: `tests/test_agent_phases.py` (budget, end_turn, auto_allow, runner, and the TUI flow with the gate).

## Compaction (`agent/compact.py`)

- `Compactor` (attached in `command.py`; the loop only calls `compactor.due()` / `.run()`) replaces the conversation by **one user message with the model's summary** (starts with `HEADER`, so `is_summary` finds it on replay) **plus the latest messages kept word for word** (at most 12K chars, or ~10% of the window: `keep_chars`). `split_point` cuts only before a user/assistant message, so a tool call is never separated from its result (the next request would be rejected).
- The summary request is the same system prompt + tools + the whole conversation + `REQUEST` (and the `/compact` focus), so the device can reuse its prompt cache. Its text is not shown as a chat message: the loop maps it to `SummaryProgress(chars)`, and the TUI shows the summary in a collapsed block after `Compacted`.
- Automatic: before a turn and after each tool step, once the last request's usage reaches `agent.compact` % of the window (default 85; `off`, or 50–95, validated by `tai config set`). Never during phased work (the phase budget wraps up and hands off instead). A failed automatic try is not repeated in the same turn (`Compactor.failed`), because each try costs a long request.
- Failure, an empty summary, or Esc leave the conversation exactly as it was (and restore the token count). `/compact [focus]` works even with `agent.compact off`.
- Saving: the compacted conversation becomes a new agent session named `compacted from session N` (`SessionSink.compacted`), so the old one stays complete. Phases use the same sink (`SessionSink.new`), and `/clear` clears the session currently being written.
- Tests: `tests/test_agent_compact.py` (split, replace, failures, automatic before/mid turn, no retry, off/phases, setting, `/compact` in the TUI).
